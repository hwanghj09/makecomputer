# 키보드와 LCD를 추가하는 원리 — MAKECOMPUTER/8

> 대상: 8비트 브레드보드 컴퓨터를 처음 만드는 사람  
> 목적: PS/2 키보드 입력을 CPU가 읽고, 20×4 문자 LCD에 출력하는 **개념과 데이터 흐름** 이해  
> 이 문서는 개념 설명서이며, 검증된 최종 배선도나 완성된 프로그램이 아니다. 핀 연결은 [08_IO_LCD.md](./08_IO_LCD.md), [09_PS2_Keyboard.md](./09_PS2_Keyboard.md)를 참조한다.

## 1. 핵심 개념

기존 컴퓨터는 RAM에 있는 명령어와 숫자를 읽어 계산했다. 키보드와 LCD를 추가하면 컴퓨터가 외부와도 데이터를 주고받는다.

```text
PS/2 키보드 → 입력 변환 회로 → CPU ↔ RAM / ROM
                                  ↓
                           출력 제어 회로 → 20×4 LCD
```

CPU가 키보드 내부 구조나 LCD의 픽셀을 직접 다룰 필요는 없다. CPU는 정해진 주소를 읽거나 쓰고, 주변 회로가 그 동작을 키보드 읽기/LCD 쓰기로 해석한다. 이 방식을 **메모리 매핑 입출력(Memory-Mapped I/O)**이라고 한다.

### 용어

| 용어 | 의미 |
|---|---|
| CPU | 명령어를 읽고 실행하는 중앙처리장치 |
| 데이터 버스(DB0~DB7) | CPU와 다른 회로 사이에 8비트 값을 전달하는 공용 선 |
| 주소 버스(A0~A7) | 접근 대상의 주소를 나타내는 8개 선 |
| I/O | 입력(Input)과 출력(Output) |
| 레지스터 | 특정 값을 유지하는 회로 |
| 디코더 | 주소·명령 비트를 보고 대상 회로를 선택하는 회로 |
| ROM / EEPROM | 미리 기록한 값을 주소에 따라 출력하는 메모리 |
| ASCII | 문자를 숫자로 나타내는 코드 체계 |

## 2. 메모리 매핑 I/O

주소가 8비트이므로 주소 0~255를 구분할 수 있다. 프로젝트의 현재 주소 계획은 아래와 같다.

| 10진 주소 | 16진 주소 | 기능 | 접근 |
|---:|---:|---|---|
| 0~159 | 0x00~0x9F | RAM 160바이트 | 읽기/쓰기 |
| 160 | 0xA0 | KEY_STATUS | 읽기 |
| 161 | 0xA1 | KEY_DATA | 읽기 |
| 162 | 0xA2 | LCD_DATA | 쓰기 |
| 163 | 0xA3 | LCD_COMMAND | 쓰기 |
| 164~255 | 0xA4~0xFF | 미할당/확장용 | 설계 필요 |

```text
CPU에서 주소 161을 지정하고 읽기 신호를 보냄
 → 주소 디코더가 KEY_DATA를 선택
 → 키보드 회로가 DB0~DB7에 8비트 문자를 출력
 → CPU가 값을 읽음

CPU에서 주소 162를 지정하고 쓰기 신호를 보냄
 → LCD_DATA가 선택됨
 → OUT 레지스터의 값과 LCD 제어 신호를 사용해 LCD로 문자 전달
```

**주소만 일치한다고 동작하는 것은 아니다.** 읽기/쓰기 구분, 디코더의 선택 신호, 버스 출력 활성화, 레지스터 갱신 타이밍도 맞아야 한다. 특히 여러 장치가 데이터 버스에 동시에 값을 출력하면 안 된다.

## 3. PS/2 키보드 입력 원리

### 3-1. 키를 누르면 문자 코드가 아니라 스캔 코드가 온다

일반적인 PS/2 Scan Code Set 2에서 A키를 **누를 때** 전송되는 스캔 코드는 `0x1C`이다. 화면에 표시할 ASCII 대문자 A는 `0x41`이다.

```text
A키 누름
 → 스캔 코드 0x1C
 → PS/2 수신 회로
 → EEPROM 변환표: 0x1C → 0x41
 → KEY_DATA
 → CPU가 0x41 읽음
```

> 이 예시는 대문자 A를 출력하도록 만든 **단순 변환표**다. 실제 소문자, Shift, Caps Lock, 키를 뗄 때의 신호는 추가 상태 처리 없이는 완전하게 구분할 수 없다.

### 3-2. PS/2는 두 신호선을 사용한다

- **CLOCK**: 키보드가 비트를 전송하는 시점을 알려준다.
- **DATA**: 실제 0 또는 1을 전달한다.
- 두 선은 일반적으로 풀업 저항을 사용하는 오픈 컬렉터/오픈 드레인 방식이다.
- PS/2는 CPU의 NE555 클럭과 **별도의 타이밍**으로 동작한다.

키보드에서 컴퓨터로 전송하는 기본 프레임은 **11비트**다.

```text
Start(0) | D0 D1 D2 D3 D4 D5 D6 D7 | Parity | Stop(1)
              8비트 스캔 코드
```

데이터는 일반적으로 **최하위 비트(LSB)부터** 전송된다. 패리티는 홀수 패리티이며, 제대로 받았는지 검사할 수 있다.

### 3-3. 신호를 처리하는 칩들의 역할

```text
PS/2 Mini-DIN 소켓
       ↓ CLOCK / DATA
74HC14 — 입력 신호 정형
       ↓
74HC161 — 현재 몇 번째 비트인지 카운트
       ↓
74HC164 ×2 — 직렬 비트를 모아 병렬 스캔 코드 생성
       ↓
AT28C64B — 스캔 코드를 ASCII 값으로 변환
       ↓
74HC157 ×2 — KEY_STATUS 또는 KEY_DATA 선택
       ↓
74HC245 — 요청받았을 때만 CPU 데이터 버스로 출력
       ↓
CPU
```

- **74HC14**: 슈미트 트리거 인버터. 느리거나 잡음이 섞인 전압 변화를 더 명확한 디지털 신호로 처리한다.
- **74HC161**: 비트 카운터. 프레임 내 위치를 추적한다.
- **74HC164**: 시프트 레지스터. 한 번에 하나씩 들어온 비트를 모아 여러 출력 핀에서 동시에 사용할 수 있게 한다.
- **AT28C64B**: 미리 기록한 변환표. 스캔 코드를 주소로 받고 해당 위치의 ASCII 값을 출력한다.
- **74HC157**: 두 데이터 후보 중 하나를 선택하는 MUX(멀티플렉서).
- **74HC245**: 선택된 입력 값만 공용 데이터 버스로 내보내는 버스 트랜시버.

### 3-4. KEY_STATUS와 KEY_DATA를 나눈 이유

CPU와 키보드가 항상 같은 속도로 동작하지 않기 때문이다.

- `KEY_STATUS`(160)의 bit0 = `KEY_READY`
  - `0`: 읽을 새 데이터 없음
  - `1`: 새 입력 데이터 준비됨
- `KEY_DATA`(161): 변환된 8비트 문자 데이터.

예상 흐름:

1. 키보드 회로가 유효한 프레임을 수신한다.
2. 변환된 데이터를 유지하고 `KEY_READY=1`로 설정한다.
3. CPU가 주소 160을 읽어 입력 준비 여부를 확인한다.
4. 준비되었다면 주소 161을 읽는다.
5. 정상적으로 읽은 뒤 ACK(수신 확인)로 `KEY_READY`를 해제한다.
6. 다음 키 입력을 받을 수 있게 한다.

이 설계에는 키 입력을 처리하는 동안 PS/2 CLOCK을 LOW로 잡아 전송을 잠시 막는 아이디어도 있다. 실제 연속 입력과 타이밍 안정성은 회로 테스트가 필요하다.

## 4. 20×4 문자 LCD 출력 원리

LCD는 한 줄에 20글자, 총 4줄을 표시하는 **HD44780 호환 문자 LCD**를 목표로 한다. 내부 컨트롤러가 문자 모양을 표시하므로 CPU가 글자의 모든 픽셀을 직접 계산하지 않는다.

### 4-1. 주요 핀의 의미

| 핀/신호 | 역할 |
|---|---|
| D0~D7 | LCD에 보내는 8비트 값 |
| RS | `0`이면 명령, `1`이면 문자 데이터 |
| R/W | `0`이면 쓰기, `1`이면 읽기 |
| E | 데이터가 확정되도록 하는 Enable 펄스 |
| VO | 화면 대비 조정 |

프로젝트 설계는 읽기 대신 쓰기만 사용하므로 `R/W`를 GND에 고정한다.

### 4-2. A를 출력하는 예시

ASCII 문자 `A`는 16진수 `0x41`, 이진수 `01000001`이다.

```text
CPU A 레지스터 = 0x41
        ↓
OUT 레지스터 = 0x41
        ↓
LCD D7~D0 = 01000001
LCD RS = 1 (문자 데이터)
LCD R/W = 0 (쓰기)
LCD E = 규격에 맞는 펄스
        ↓
LCD에 A 표시
```

반면 `RS=0`이고 `0x01`을 쓰면 일반적인 HD44780에서는 **화면 지우기 명령**이다. 즉 **같은 데이터선이라도 RS가 데이터/명령을 구분**한다.

현재 주소 계획에서는 `162 = LCD_DATA`, `163 = LCD_COMMAND`이다. **주의:** HD44780 자체는 `RS=1`이 데이터, `RS=0`이 명령이다. 저장소의 `08_IO_LCD.md`에 적힌 `LCD_COMMAND_N`을 RS에 바로 연결하는 방법은 활성 Low 극성과 주소 선택 타이밍을 별도로 확인해야 한다. 단순히 신호 이름만 보고 연결이 올바르다고 가정하면 안 된다.

### 4-3. 왜 초기화가 필요한가?

LCD는 전원을 켠 직후 사용 모드가 준비되었다고 가정할 수 없다. 프로그램이 LCD 규격에 맞춰 초기화 명령과 대기시간을 제공해야 한다.

대표적으로:

1. 전원 인가 후 규정된 시간 대기
2. 8비트 인터페이스 모드 설정
3. 표시 ON 설정
4. 커서 이동 방향 등 Entry Mode 설정
5. 필요하다면 화면 지우기

일반적인 문자 쓰기보다 화면 지우기 등 일부 명령은 처리시간이 더 길다. R/W를 GND에 묶었으므로 Busy Flag를 읽을 수 없고, 충분한 대기시간을 프로그램이나 회로가 보장해야 한다.

## 5. 키보드에서 입력한 A를 LCD에 보여주는 전체 흐름

```text
[키보드에서 A 누름]
         │
         ▼
PS/2 스캔 코드 0x1C 송신
         │
         ▼
74HC14 + 비트 카운터 + 74HC164
         │
         ▼
AT28C64B 변환표 → ASCII 0x41
         │
         ▼
KEY_READY=1, KEY_DATA=0x41
         │
         ▼
CPU가 160을 읽어 READY 확인
         │
         ▼
CPU가 161을 읽고 0x41을 A 레지스터에 저장
         │
         ▼
CPU가 162에 0x41을 쓰는 출력 동작
         │
         ▼
OUT 레지스터 + RS=1 + LCD E 펄스
         │
         ▼
LCD에 A 표시
```

여기서 CPU의 주된 역할은 복잡한 수학 연산이 아니라 **상태 확인, 데이터 읽기, 데이터 전달, 출력 제어**다.

### 개념적 의사코드

아래는 동작 원리를 설명하는 **의사코드**이다. 현재 13개 명령어의 인코딩과 마이크로스텝이 모두 검증된 실행 가능한 기계어 프로그램이라는 뜻이 아니다.

```text
LCD 초기화

반복:
    status ← READ(160)            ; KEY_STATUS
    if (status AND 1) == 0:
        goto 반복

    character ← READ(161)         ; KEY_DATA
    WRITE(162, character)         ; LCD_DATA
    입력 수신 ACK
    goto 반복
```

## 6. 설계와 검증을 구분하기

GitHub의 상세 단계별 설명은 **구현 예정 회로의 설명서**다. 실제 브레드보드 동작까지 확인되었다는 증거는 아니다.

| 검증할 항목 | 이유 |
|---|---|
| PS/2 시작/정지/패리티 확인 | 잘못 받은 비트를 문자로 오인하지 않기 위해 |
| 시프트 레지스터 비트 순서 | LSB부터 전송되는 코드가 정확히 재구성되는지 확인 |
| 키 누름/뗌/Shift 상태 | Scan Code 한 바이트의 단순 변환만으로 해결되지 않기 때문에 |
| KEY_READY와 ACK | 키 입력 유실과 중복 처리를 막기 위해 |
| 읽기/쓰기 주소 디코딩 | RAM과 I/O가 잘못 동시에 활성화되지 않도록 |
| LCD RS 극성과 E 펄스 | 문자와 명령이 정확한 시점에 확정되도록 |
| LCD 초기화·대기시간 | 문자 LCD가 안정적으로 동작하도록 |
| CPU의 실제 명령어·제어 단계 | `READ/WRITE` 의사코드를 실제 T0~T5 실행으로 구현할 수 있는지 확인 |

## 7. 먼저 할 수 있는 독립 테스트

1. **키보드 없이 LCD 테스트:** 전원·대비 확인 → 수동으로 초기화 명령 전달 → `0x41`을 쓰고 A 표시 확인.
2. **CPU 없이 키보드 테스트:** PS/2 CLOCK/DATA 측정 → 11비트 프레임 수신 → A키 스캔 코드 `0x1C` 확인 → EEPROM에서 `0x41` 출력 확인.
3. **I/O 주소만 테스트:** 주소 160, 161, 162, 163을 순서대로 지정해 각 선택 신호가 하나씩만 활성화되는지 확인.
4. **CPU 통합 테스트:** KEY_READY 확인 → KEY_DATA 읽기 → LCD_DATA 쓰기 → ACK → 연속 키 입력 시험.
