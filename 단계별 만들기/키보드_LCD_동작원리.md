# 키보드와 화면은 어떻게 작동할까?

우리가 만드는 8비트 컴퓨터에 **PS/2 키보드**와 **20×4 문자 LCD**를 연결하면, 키보드로 입력한 글자를 CPU가 읽고 화면에 표시할 수 있다.

## 1. CPU는 키보드와 화면을 어떻게 구분할까?

CPU는 키보드나 화면을 직접 알아보는 것이 아니라 **주소**로 구분한다. 이것을 **메모리 매핑 입출력(Memory-Mapped I/O)**이라고 한다. RAM을 읽고 쓰듯이 정해진 주소를 읽거나 쓰는 방식이다.

| 주소 | 역할 |
|---|---|
| 0~159 | RAM |
| 160 | 키보드에 새 입력이 있는지 확인 |
| 161 | 키보드에서 받은 문자 읽기 |
| 162 | LCD에 문자 보내기 |
| 163 | LCD에 제어 명령 보내기 |

예를 들어 CPU가 주소 **161**을 읽으면 키보드의 문자 데이터를 받고, 주소 **162**에 값을 쓰면 그 값을 LCD에 전달하는 구조다.

## 2. 키보드에서 A를 누르면?

키보드는 처음부터 문자 'A'를 보내는 것이 아니라 **스캔 코드(어떤 키를 눌렀는지 나타내는 숫자)**를 보낸다.

```text
A키 누름
   ↓
PS/2 키보드가 스캔 코드 0x1C 전송
   ↓
74HC14: 입력 신호 정리
   ↓
74HC161 + 74HC164: 순서대로 들어오는 비트 수집
   ↓
AT28C64B ROM: 0x1C를 ASCII 0x41('A')로 변환
   ↓
CPU가 주소 161에서 0x41 읽기
```

PS/2는 **CLOCK**(언제 읽을지 알려주는 선)과 **DATA**(0과 1을 보내는 선)를 사용한다. 한 번 전송할 때 시작 비트, 데이터 8비트, 검사 비트, 종료 비트를 합쳐 **11비트**가 들어온다.

CPU가 키보드보다 느릴 수 있으므로, 입력 회로는 **KEY_READY**라는 신호로 새 문자가 준비되었음을 알려준다. CPU는 주소 160을 확인하고 준비되었다면 주소 161을 읽는다. 읽은 뒤에는 수신 완료를 알리고 다음 입력을 받는다.

> 여기서는 이해를 위해 A키를 대문자 A로 변환하는 예시를 들었다. 실제 Shift, Caps Lock, 키를 뗄 때의 신호까지 처리하려면 회로를 더 검증해야 한다.

## 3. LCD에는 어떻게 글자를 표시할까?

20×4 LCD는 한 줄에 20글자씩 네 줄을 표시한다. LCD 안에는 문자 모양을 표시하는 기능이 있어서 CPU가 픽셀을 하나하나 그릴 필요가 없다.

예를 들어 CPU가 'A'를 표시하려면 다음과 같이 동작한다.

```text
CPU가 문자 A의 ASCII 값 0x41 준비
   ↓
OUT 레지스터가 0x41을 유지
   ↓
LCD 데이터선 D0~D7로 전달
   ↓
RS=1 (문자 데이터), R/W=0 (쓰기)
   ↓
E 신호를 주어 LCD에 데이터 전달
   ↓
화면에 A 표시
```

LCD는 글자뿐 아니라 화면 지우기, 커서 이동 같은 **명령**도 받는다. **RS** 신호는 문자 데이터와 명령을 구분하고, **E** 신호는 데이터를 실제로 받아들이도록 한다. 전원을 켠 직후에는 LCD 초기화도 필요하다.

## 4. 전체 흐름 한눈에 보기

```text
[키보드에서 A 입력]
          ↓
스캔 코드 수신 → ASCII 'A'(0x41)로 변환
          ↓
KEY_READY 확인 → CPU가 문자 읽기
          ↓
CPU가 LCD 출력값 준비
          ↓
LCD에 문자 전달
          ↓
       [A 표시]
```

**핵심은 CPU가 새로운 문자 처리 능력을 갖는 것이 아니라, 기존의 데이터 읽기·쓰기 기능으로 키보드와 LCD를 제어한다는 점이다.**

이 문서는 **원리 설명**이다. 실제 제작에서는 PS/2 비트 순서, 입력 완료 신호, LCD의 RS/E 극성과 타이밍, CPU 명령어 실행을 확인해야 한다. 특히 LCD 주소 선택 신호를 RS에 연결하는 부분은 논리 극성이 올바른지 검증이 필요하다.
