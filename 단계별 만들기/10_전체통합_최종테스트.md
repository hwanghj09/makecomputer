# 10단계 — 전체 통합 최종 테스트

> 지금까지 각각 단독 테스트를 통과한 회로만 하나씩 합친다. 문제가 생기면 전체를 뜯지 말고 마지막으로 추가한 부분부터 확인한다.

이 파일에서도 칩 번호 별칭을 쓰지 않는다.

---

아래 순서를 바꾸지 않는다.

1. NE555 클럭 발생기

7. 74HC245 RAM 데이터 버스 드라이버
8. 74HC245 수동 입력 버스 드라이버
9. 74HC273 A 레지스터
10. 74HC86 XOR 두 개 + 74HC283 ALU 두 개
11. 74HC157 A/ALU 선택 MUX 두 개
12. 74HC245 A/ALU 데이터 버스 드라이버
13. 74HC273 명령어 레지스터
14. 74HC139 기본 명령 디코더

18. 전체 74HC08/74HC32/74HC04 제어 논리

23. PS/2 키보드 회로

각 항목을 추가한 뒤 이전 테스트가 그대로 정상인지 다시 본다.

# 10-2. DATA BUS 충돌 확인

한 순간에 DATA BUS를 직접 구동하는 장치는 원칙적으로 하나다.

| 동작 | DATA BUS를 구동해야 하는 장치 |
|---|---|
| Monitor 명령 Fetch | 74HC245 Boot ROM 데이터 버스 드라이버 |
| RAM 명령 Fetch / LDA | 74HC245 RAM 데이터 버스 드라이버 |
| ADD/SUB 결과 | 74HC245 A/ALU 데이터 버스 드라이버 |
| CMP | DATA BUS Driver 모두 OFF |
| Keyboard LDA | 74HC245 키보드 데이터 버스 드라이버 |
| STA RAM | A/ALU 버스 드라이버가 BUS를 구동하고 RAM 버스 드라이버는 BUS→RAM 방향 |

## 확인 방법

각 74HC245의 19번 `/OE`를 로직 프로브나 LED로 확인한다.

두 개 이상의 버스 드라이버가 동시에 LOW(`/OE` 활성)가 되는 상황이 있으면 즉시 수정한다.

# 10-3. Reset 테스트

Reset 버튼을 눌렀을 때 최소한 다음 상태가 되어야 한다.

- Program Counter = 0
- A 레지스터 = 0
- 명령어 레지스터 = 0
- 메모리 주소 레지스터 = 0
- 출력 레지스터 = 0
- Z Flag = 0
- MONITOR_MODE = 1
- HALT 해제
- 마이크로스텝 = T0

Reset 후 Clock이 다시 정상적으로 전달되는지도 확인한다.

---

# 10-4. 첫 프로그램은 가장 작게 시작

처음부터 RAM, 키보드, LCD, 조건점프를 전부 시험하지 않는다.

가장 먼저 아래 프로그램만 시험한다.

```text
LDI 5
OUT
HLT
```

확인 순서:

1. 명령어 Fetch에서 명령어 레지스터가 LDI를 읽는지 확인
2. LDI의 Operand 단계에서 A 레지스터에 5가 저장되는지 확인
3. OUT 마지막 단계에서 출력 레지스터에 5가 저장되는지 확인
4. HLT 이후 RUN_EN이 LOW가 되어 CPU Clock이 멈추는지 확인
5. Reset하면 다시 처음부터 실행할 수 있는지 확인

이 프로그램이 완전히 성공하기 전에는 다음 명령으로 가지 않는다.

---

# 10-5. 명령어를 하나씩 늘려서 시험

다음 순서로 추가한다.

## 1. LDA / STA

RAM 특정 주소에 값을 저장하고 다시 A로 읽어온다.

예:

```text
LDI 42
STA 10
LDA 10
OUT
HLT
```

출력 레지스터가 42면 정상이다.

## 2. ADD

```text
LDI 5
STA 10
LDI 3
ADD 10
OUT
HLT
```

결과가 8이어야 한다.

## 3. SUB

5-3=2 같은 작은 값부터 확인한다.

## 4. JMP

지정한 주소로 Program Counter가 바뀌는지 확인한다.

## 5. CMP

A와 RAM 값이 같을 때 Z Flag=1인지 확인한다.

## 6. JZ

Z=1일 때만 점프하는지 확인한다.

## 7. JNZ

Z=0일 때만 점프하는지 확인한다.

## 8. RUN

RUN을 실행했을 때:

- Program Counter가 지정 주소로 바뀜
- MONITOR_MODE가 0이 됨
- 다음 명령부터 RAM에서 Fetch

인지 확인한다.

---

# 10-6. Boot ROM 테스트

Monitor ROM 전체 프로그램을 넣기 전에 테스트 패턴부터 확인한다.

1. Boot ROM 주소 0~몇 바이트에 눈에 띄는 패턴 기록
2. Reset
3. Program Counter를 증가시키며 Boot ROM 출력 확인
4. MONITOR_MODE=1에서 Boot ROM 버스 드라이버만 DATA BUS를 구동하는지 확인
5. RUN 후 MONITOR_MODE=0에서 Boot ROM 버스 드라이버가 꺼지는지 확인

---

# 10-7. LCD 테스트

순서:

1. LCD 전원/대비 확인
2. 초기화 명령 확인
3. 문자 `A` 하나 출력
4. 문자열 출력
5. Clear 명령
6. Monitor 메시지 출력

목표 화면 예:

```text
MAKECOMPUTER/8
SYSTEM READY
> _
```

---

# 10-8. PS/2 키보드 테스트

1. A키 입력
2. KEY_READY=1 확인
3. KEY_DATA=0x41 확인
4. KEY_DATA를 읽은 뒤 KEY_READY가 0으로 돌아가는지 확인
5. B,C,D 등 여러 키 확인
6. LCD에 입력 문자가 그대로 표시되는지 확인

---

# 10-9. 최종 Monitor 기능 시험

최종 목표 명령:

```text
H       HELP
M aa    MEMORY READ
S aa vv MEMORY WRITE
R aa    RUN
C       CLEAR LCD
```

각 명령을 하나씩 시험한다.

특히 `R aa` 실행 후 RAM 프로그램으로 넘어갔다가 Reset으로 다시 Monitor에 돌아오는지 확인한다.

# 문제가 생기면

전체를 한꺼번에 의심하지 않는다.

```text
방금 추가한 회로 분리
↓
이전 상태가 정상인지 확인
↓
추가한 회로만 단독 테스트
↓
전원/핀 번호/제어신호 확인
↓
다시 연결
```

이 방식으로 진행하면 수십 개 IC가 있어도 문제 위치를 찾을 수 있다.
