# 10단계 — 전체 통합 최종 테스트

> 지금까지 각각 단독 테스트를 통과한 회로만 하나씩 합친다. 문제가 생기면 전체를 뜯지 말고 마지막으로 추가한 부분부터 확인한다.

이 파일에서도 칩 번호 별칭을 쓰지 않는다. 항상 **부품명 + 역할 + 실제 핀 번호**로 확인한다.

## 이 단계의 점퍼선 색

- 🟥 **빨강** = +5V / HIGH 고정
- ⬛ **검정** = GND / LOW 고정
- 🟩 **초록** = DATA
- 🟨 **노랑** = ADDRESS
- 🟦 **파랑** = CLOCK / RESET / CLEAR
- 🟧 **주황** = CONTROL
- ⬜ **흰색** = STATUS / FLAG / SPECIAL

> **10단계에서는 새로운 종류의 점퍼선을 추가하지 않는다.** 1~9단계에서 만든 선의 색이 맞는지 다시 검산하면서 전체를 합치는 단계다.

# 10-1. 통합 순서

아래 순서를 바꾸지 않는다.

1. NE555 클럭 발생기
2. 74HC161 PC 하위·상위 카운터
3. 74HC273 메모리 주소 레지스터
4. 74HC157 주소 선택 MUX 하위·상위칩
5. 74HC138 RAM 뱅크 디코더
6. CDP1824CE RAM #1~#5
7. 74HC245 RAM 데이터 버스 드라이버
8. 74HC245 수동 입력 버스 드라이버
9. 74HC273 A 레지스터
10. 74HC86 XOR 두 개 + 74HC283 ALU 두 개
11. 74HC157 A/ALU 선택 MUX 두 개
12. 74HC245 A/ALU 데이터 버스 드라이버
13. 74HC273 명령어 레지스터
14. 74HC139 기본 명령 디코더
15. 74HC161 마이크로스텝 카운터 + 74HC138 마이크로스텝 디코더
16. 74HC139 확장 명령 디코더 + 확장명령 유효 검출
17. 74HC273 출력 레지스터
18. 전체 74HC08/74HC32/74HC04 제어 논리
19. 74HC74 Z Flag·MONITOR_MODE 저장칩
20. 74HC74 KEY_READY·HALT 저장칩
21. AT28C64B Monitor Boot ROM + 74HC245 Boot ROM 버스 드라이버
22. 74HC138 메모리 맵 I/O 주소 디코더 + LCD
23. PS/2 키보드 회로

각 항목을 추가한 뒤 이전 테스트가 그대로 정상인지 다시 본다.

# 10-2. 전체 점퍼선 색 검산

완성된 회로를 보면서 다음 기준으로 한 줄씩 확인한다.

## 🟥 빨강 — POWER +5V

확인할 것:

- 모든 74HC 계열 VCC 핀
- CDP1824CE RAM VDD 핀
- AT28C64B EEPROM VCC 핀
- LCD VDD
- +5V에 고정한 Enable/DIR/WE 등의 입력
- 각 0.1µF 디커플링 커패시터의 VCC 쪽

**빨강 선이 DATA/ADDRESS 핀으로 잘못 들어가 있으면 안 된다.**

## ⬛ 검정 — GND

확인할 것:

- 모든 IC GND/VSS 핀
- GND에 고정한 사용하지 않는 입력
- LCD VSS/RW/LED-
- EEPROM에서 사용하지 않는 상위 주소를 LOW로 고정한 선
- 각 0.1µF 디커플링 커패시터의 GND 쪽

## 🟩 초록 — DATA

확인할 것:

- DB0~DB7 CPU DATA BUS
- RAM_D0~RAM_D7
- A 레지스터 입력/출력 데이터
- ALU 데이터 경로
- Boot ROM I/O0~I/O7
- ASCII ROM I/O0~I/O7
- LCD D0~D7
- PS/2 DATA 직렬선

## 🟨 노랑 — ADDRESS

확인할 것:

- PC0~PC7 → 주소 선택 MUX
- MAR0~MAR7 → 주소 선택 MUX
- ADDRESS A0~A7
- RAM 주소선 A0~A4
- Boot ROM A0~A7
- Scan Code→ASCII ROM A0~A7
- 메모리 맵 I/O 주소 입력

## 🟦 파랑 — CLOCK / RESET / CLEAR

확인할 것:

- NE555 Clock
- CPU Clock
- PC Clock
- A/MAR/IR/OUT Clock
- RESET_N
- KEY_CLR_N
- PS2_SAMPLE_CLK
- FRAME_CLK
- PS/2 CLOCK

## 🟧 주황 — CONTROL

확인할 것:

- `/OE`
- `DIR`
- RAM `CS/MRD/MWR`
- MUX Select
- PC `/LOAD`
- Opcode Decoder 출력
- Microstep Decoder 출력
- LCD RS/E
- 각종 Enable/Read/Write 신호

## ⬜ 흰색 — STATUS / FLAG / SPECIAL

확인할 것:

- Z / Z_N
- MONITOR_MODE / MONITOR_N
- KEY_READY / KEY_READY_N
- HALT / RUN_EN
- PS/2 비트 카운터 상태 QA~QD
- COUNT11 / HIGHPAIR / LOWPAIR
- LCD VO 대비 조절선

# 10-3. DATA BUS 충돌 확인

한 순간에 DATA BUS를 직접 구동하는 장치는 원칙적으로 하나다.

| 동작 | DATA BUS를 구동해야 하는 장치 | DATA 선 색 |
|---|---|---|
| Monitor 명령 Fetch | 74HC245 Boot ROM 데이터 버스 드라이버 | 🟩 초록 |
| RAM 명령 Fetch / LDA | 74HC245 RAM 데이터 버스 드라이버 | 🟩 초록 |
| ADD/SUB 결과 | 74HC245 A/ALU 데이터 버스 드라이버 | 🟩 초록 |
| CMP | DATA BUS Driver 모두 OFF | - |
| Keyboard LDA | 74HC245 키보드 데이터 버스 드라이버 | 🟩 초록 |
| STA RAM | A/ALU 버스 드라이버가 BUS 구동 + RAM 버스 드라이버는 BUS→RAM 방향 | 🟩 초록 |

## 확인 방법

각 74HC245의 19번 `/OE`는 🟧 **주황 CONTROL 선**이어야 한다.

두 개 이상의 버스 드라이버가 동시에 LOW(`/OE` 활성)가 되는 상황이 있으면 즉시 수정한다.

# 10-4. Reset 테스트

Reset 버튼과 RESET_N 배선은 🟦 **파랑**이다.

Reset 버튼을 눌렀을 때 최소한 다음 상태가 되어야 한다.

- Program Counter = 0
- A 레지스터 = 0
- 명령어 레지스터 = 0
- 메모리 주소 레지스터 = 0
- 출력 레지스터 = 0
- Z Flag = 0
- MONITOR_MODE = 1
- HALT 해제
- 마이크로스텝 = T0

Reset 후 🟦 CPU Clock이 다시 정상적으로 전달되는지도 확인한다.

---

# 10-5. 첫 프로그램은 가장 작게 시작

처음부터 RAM, 키보드, LCD, 조건점프를 전부 시험하지 않는다.

```text
LDI 5
OUT
HLT
```

확인 순서:

1. 🟩 DATA BUS를 통해 명령어 레지스터가 LDI를 읽는지 확인
2. LDI Operand에서 A 레지스터에 5가 저장되는지 확인
3. OUT 마지막 단계에서 출력 레지스터에 5가 저장되는지 확인
4. ⬜ RUN_EN이 LOW가 되어 🟦 CPU Clock이 막히는지 확인
5. 🟦 Reset하면 다시 처음부터 실행되는지 확인

이 프로그램이 완전히 성공하기 전에는 다음 명령으로 가지 않는다.

---

# 10-6. 명령어를 하나씩 늘려서 시험

## 1. LDA / STA

```text
LDI 42
STA 10
LDA 10
OUT
HLT
```

확인할 선:
- 🟨 ADDRESS가 10을 가리키는지
- 🟩 DATA가 42인지
- 🟧 RAM Read/Write 제어가 맞는지

## 2. ADD

```text
LDI 5
STA 10
LDI 3
ADD 10
OUT
HLT
```

결과가 8이어야 한다.

## 3. SUB

5-3=2부터 확인한다.

## 4. JMP

🟨 Program Counter 주소가 지정 주소로 바뀌는지 확인한다.

## 5. CMP

A와 RAM 값이 같을 때 ⬜ Z Flag=1인지 확인한다.

## 6. JZ

Z=1일 때만 점프하는지 확인한다.

## 7. JNZ

Z=0일 때만 점프하는지 확인한다.

## 8. RUN

RUN 후:

- 🟨 Program Counter가 지정 주소로 바뀜
- ⬜ MONITOR_MODE가 0
- 다음 명령부터 RAM에서 Fetch

인지 확인한다.

---

# 10-7. Boot ROM 테스트

1. Boot ROM 주소 0~몇 바이트에 테스트 패턴 기록
2. 🟦 Reset
3. 🟨 Program Counter를 증가시키며 Boot ROM 출력 확인
4. ⬜ MONITOR_MODE=1에서 Boot ROM 버스 드라이버만 🟩 DATA BUS를 구동하는지 확인
5. RUN 후 MONITOR_MODE=0에서 🟧 Boot ROM `/OE`가 비활성인지 확인

---

# 10-8. LCD 테스트

1. 🟥/⬛ LCD 전원 확인
2. ⬜ VO 대비 확인
3. 🟧 초기화 명령/RS/E 확인
4. 🟩 문자 `A` 데이터 전송
5. 문자열 출력
6. Clear 명령
7. Monitor 메시지 출력

목표 화면:

```text
MAKECOMPUTER/8
SYSTEM READY
> _
```

---

# 10-9. PS/2 키보드 테스트

1. A키 입력
2. 🟦 PS/2 CLOCK 확인
3. 🟩 PS/2 DATA 확인
4. ⬜ KEY_READY=1 확인
5. 🟩 KEY_DATA=0x41 확인
6. KEY_DATA를 읽은 뒤 KEY_READY가 0으로 돌아가는지 확인
7. B,C,D 등 여러 키 확인
8. LCD에 입력 문자가 그대로 표시되는지 확인

---

# 10-10. 최종 Monitor 기능 시험

```text
H       HELP
M aa    MEMORY READ
S aa vv MEMORY WRITE
R aa    RUN
C       CLEAR LCD
```

각 명령을 하나씩 시험한다.

특히 `R aa` 실행 후 RAM 프로그램으로 넘어갔다가 🟦 Reset으로 다시 Monitor에 돌아오는지 확인한다.

# 문제가 생기면

```text
방금 추가한 회로 분리
↓
이전 상태가 정상인지 확인
↓
추가한 회로만 단독 테스트
↓
점퍼선 색과 핀 번호 확인
↓
전원/제어신호 확인
↓
다시 연결
```

특히 같은 물리 선의 양쪽 문서에서 색이 다르게 적혀 있으면 그대로 배선하지 말고 먼저 문서를 수정해야 한다.
