# 10단계 — 전체 통합 최종 테스트

지금까지는 각 블록을 따로 만들고 시험했다.
이번 단계에서는 모든 블록을 합쳐 **실제 8비트 컴퓨터로 동작하는지** 확인한다.

가장 중요한 원칙:

> 문제가 생기면 전체를 뜯지 않는다. **마지막으로 추가한 블록부터** 확인한다.

그리고 최종 테스트에서도 항상 **부품 역할 + 핀 번호 + 신호 이름**으로 추적한다.

---

# 10-1. 통합 순서

아래 순서로 하나씩 합친다.

1. NE555 Clock
2. 74HC161 PC 하위·상위
3. 74HC273 MAR
4. 74HC157 주소 선택 MUX 하위·상위
5. 74HC138 RAM 뱅크 디코더
6. CDP1824CE RAM #1~#5
7. 245 #1 = RAM DATA BUS Driver
8. 245 #2 = 수동 입력 Driver
9. 74HC273 A 레지스터
10. 74HC86 두 개 + 74HC283 두 개 ALU
11. 74HC157 A/ALU 선택 MUX 두 개
12. 74HC245 A/ALU DATA BUS Driver
13. 74HC273 IR
14. 74HC139 기본 명령 디코더
15. 74HC161 Microstep + 74HC138 Microstep Decoder
16. 74HC139 확장 명령 회로
17. 74HC273 OUT 레지스터
18. 74HC08 / 74HC32 / 74HC04 제어 논리
19. 74HC74 Z Flag / MONITOR_MODE
20. 74HC74 KEY_READY / HALT
21. AT28C64B Boot ROM + 74HC245 Boot ROM Driver
22. 74HC138 I/O 주소 디코더 + LCD
23. PS/2 키보드 회로

각 항목을 추가한 직후 **이전 단계 테스트가 여전히 정상인지** 다시 확인한다.

# 10-2. 전원부터 전체 점검

CPU를 자동 실행하기 전에 전원부터 확인한다.

## 공통 기준

74HC 계열:

```text
VCC 핀 → +5V
GND 핀 → GND
```

CDP1824CE:

```text
18번 VDD → +5V
9번 VSS → GND
```

AT28C64B:

```text
28번 VCC → +5V
14번 GND → GND
```

LCD:

```text
2번 VDD → +5V
1번 VSS → GND
```

## 멀티미터 테스트

각 브레드보드에서:

```text
+5V ↔ GND ≈ 5V
```

인지 확인한다.

Clock을 연결했을 때 어떤 보드의 전압이 사라지거나 크게 떨어지면 다음으로 가지 않는다.

## 공통 GND

모든 브레드보드의 GND가 서로 연결되어 있어야 한다.

특히 다음 핀들의 GND가 같은 기준 전압이어야 한다.

```text
NE555 1번
74HC161 8번
74HC273 10번
74HC157 8번
74HC138 8번
74HC245 10번
CDP1824CE 9번
74HC08/32/04/14 7번
AT28C64B 14번
```

# 10-3. DATA BUS 충돌 확인

DATA BUS는 여러 장치가 함께 사용하지만 **한 순간에 데이터를 출력하는 장치는 원칙적으로 하나**여야 한다.

중요한 Driver의 활성 핀:

```text
RAM쪽 245 #1        19번 /OE
수동 입력 245 #2    19번 /OE
A/ALU 74HC245       19번 /OE
Boot ROM 74HC245    19번 /OE
Keyboard 74HC245    19번 /OE
```

`19번 /OE`는 Active-Low다.

```text
LOW  → 해당 칩이 DATA BUS를 구동
HIGH → DATA BUS에서 분리
```

## 자동 실행 전

수동 입력을 사용하지 않는다면:

```text
245 #2 19번 → +5V
```

로 꺼둔다.

## 동작별 정상 상태

| 동작 | DATA BUS를 구동해야 하는 장치 |
|---|---|
| Boot ROM 명령 Fetch | Boot ROM 74HC245 |
| RAM 명령 Fetch | RAM쪽 245 #1 |
| LDA | RAM쪽 245 #1 |
| ADD/SUB 결과를 BUS로 보낼 때 | A/ALU 74HC245 |
| CMP | 필요한 DATA BUS Driver는 모두 OFF |
| Keyboard Read | Keyboard 74HC245 |
| STA | A/ALU Driver가 BUS 구동, RAM쪽 245 #1은 BUS→RAM 방향 |

두 개 이상의 Driver가 서로 다른 값을 동시에 출력하면 전압이 비정상적으로 보이거나 칩이 뜨거워질 수 있다.

# 10-4. ADDRESS 경로 다시 확인

## PC 출력

```text
PC 하위
14번 = PC0
13번 = PC1
12번 = PC2
11번 = PC3

PC 상위
14번 = PC4
13번 = PC5
12번 = PC6
11번 = PC7
```

## MAR 출력

```text
2번  = MAR0
5번  = MAR1
6번  = MAR2
9번  = MAR3
12번 = MAR4
15번 = MAR5
16번 = MAR6
19번 = MAR7
```

## 주소 선택 MUX

```text
두 74HC157 1번 S = LOW  → PC 선택
두 74HC157 1번 S = HIGH → MAR 선택
```

출력:

```text
하위 MUX 4번  = A0
하위 MUX 7번  = A1
하위 MUX 9번  = A2
하위 MUX 12번 = A3
상위 MUX 4번  = A4
상위 MUX 7번  = A5
상위 MUX 9번  = A6
상위 MUX 12번 = A7
```

자동 제어에서는 `ADDR_SEL`이 이 두 MUX의 1번을 제어한다.

# 10-5. Reset 테스트

전체 회로를 연결한 상태에서 Reset 한 번으로 초기 상태가 제대로 만들어지는지 확인한다.

Reset 후 최소 목표:

```text
Program Counter = 0
A 레지스터 = 0
IR = 0
MAR = 0
OUT = 0
Z Flag = 0
MONITOR_MODE = 1
HALT = 0
RUN_EN = 1
Microstep = T0
```

그리고 CPU Clock이 다시 정상적으로 전달되어야 한다.

## 특히 측정할 곳

```text
PC 두 74HC161 출력
A 74HC273 Q0~Q7
IR 74HC273 Q0~Q7
MAR 74HC273 Q0~Q7
OUT 74HC273 Q0~Q7
MONITOR_MODE 74HC74 9번
RUN_EN 74HC74 8번
Microstep 74HC138 15번 Y0
```

# 10-6. Clock과 Microstep 확인

프로그램을 실행하기 전에 먼저 CPU가 안정적으로 단계를 진행하는지 본다.

## Clock

```text
NE555 3번 = RAW_CLK
↓
74HC08 CPU Clock 칩 3번 = CPU_CLK
```

RUN_EN이 HIGH일 때 CPU_CLK가 움직여야 한다.

HALT 상태에서는:

```text
RUN_EN = LOW
CPU_CLK 정지
```

해야 한다.

## Microstep

마이크로스텝 74HC138 출력에서:

```text
T0 → T1 → T2 → T3 → T4 → T5 → T0
```

가 반복되는지 확인한다.

---

# 10-7. 첫 프로그램은 가장 단순하게

처음부터 RAM, 키보드, LCD, 조건점프를 모두 시험하지 않는다.

첫 프로그램:

```text
LDI 5
OUT
HLT
```

## 확인 순서

### 1. LDI Fetch

IR에 LDI 명령 코드가 저장되는지 확인한다.

### 2. Operand 5

A 레지스터 Q7~Q0이:

```text
00000101
```

이 되는지 확인한다.

### 3. OUT

OUT 레지스터에도:

```text
00000101
```

이 저장되는지 확인한다.

### 4. HLT

HLT 실행 후:

```text
HALT = HIGH
RUN_EN = LOW
CPU_CLK 정지
```

인지 확인한다.

### 5. Reset

Reset하면 다시 처음 상태로 돌아가 프로그램을 다시 실행할 수 있어야 한다.

이 프로그램이 완전히 성공하기 전에는 더 복잡한 명령으로 넘어가지 않는다.

# 10-8. LDA / STA 테스트

프로그램:

```text
LDI 42
STA 10
LDA 10
OUT
HLT
```

기대 결과:

```text
RAM 주소 10 = 42
A 레지스터 = 42
OUT = 42
```

## STA 때 확인

```text
ADDRESS = 10
A/ALU Driver가 DATA BUS 구동
RAM쪽 245 #1 DIR = BUS→RAM
RAM 16번 MRD = HIGH
RAM 17번 MWR = Write pulse
```

## LDA 때 확인

```text
ADDRESS = 10
RAM 17번 MWR = HIGH
RAM 16번 MRD = LOW
RAM쪽 245 #1 방향 = RAM→BUS
A_CLK 발생
```

---

# 10-9. ADD 테스트

프로그램:

```text
LDI 5
STA 10
LDI 3
ADD 10
OUT
HLT
```

기대 결과:

```text
3 + 5 = 8
OUT = 00001000
```

확인:

```text
SUB_MODE = LOW
ALU 결과 = 8
A 레지스터가 결과 8 저장
```

---

# 10-10. SUB 테스트

가장 먼저:

```text
5 - 3 = 2
```

를 시험한다.

확인:

```text
SUB_MODE = HIGH
두 74HC86에서 RAM 데이터 반전
하위 74HC283 7번 CIN = HIGH
ALU 결과 = 00000010
```

---

# 10-11. JMP 테스트

JMP 명령을 실행할 때:

```text
PC 두 74HC161 9번 /LOAD가 필요한 순간 LOW
```

가 되어 지정 주소가 PC에 Load되는지 확인한다.

점프 후 다음 Fetch 주소가 실제 지정 주소인지 확인한다.

---

# 10-12. CMP / Z Flag 테스트

A와 비교 대상 RAM 값이 같게 만든다.

예:

```text
A = 5
RAM = 5
```

CMP 후:

```text
ALU 결과 = 0
ZERO = HIGH
Z Flag = HIGH
```

가 되어야 한다.

다른 값을 비교하면 Z가 LOW가 되어야 한다.

---

# 10-13. JZ / JNZ 테스트

## JZ

```text
Z=1 → 점프
Z=0 → 점프하지 않음
```

## JNZ

```text
Z=0 → 점프
Z=1 → 점프하지 않음
```

두 경우를 각각 시험한다.

---

# 10-14. RUN / Monitor Mode 테스트

Reset 직후:

```text
MONITOR_MODE = 1
```

이므로 Boot ROM에서 명령을 Fetch한다.

RUN 명령 실행 후:

```text
PC = 지정한 RAM 프로그램 주소
MONITOR_MODE = 0
```

가 되어야 한다.

그 다음 Fetch는 RAM에서 이루어져야 한다.

Reset을 누르면 다시:

```text
MONITOR_MODE = 1
PC = 0
```

으로 돌아와 Boot ROM Monitor가 실행되어야 한다.

---

# 10-15. Boot ROM 테스트

처음에는 복잡한 Monitor 프로그램 대신 단순 패턴으로 시험해도 된다.

예:

```text
ROM[0] = AA
ROM[1] = 55
ROM[2] = F0
```

Reset 후 PC를 증가시키며 Boot ROM 출력이 주소와 맞는지 확인한다.

MONITOR_MODE=1일 때:

```text
Boot ROM 245만 DATA BUS를 구동
```

해야 한다.

RUN 후 MONITOR_MODE=0일 때 Boot ROM 245의 19번 `/OE`가 비활성 상태가 되는지 확인한다.

---

# 10-16. LCD 테스트

다음 순서로 확인한다.

1. LCD 1번/2번 사이 약 5V
2. LCD 3번 VO로 대비 조절
3. LCD 5번 R/W = GND
4. 초기화 명령 전송
5. LCD 4번 RS 정상
6. LCD 6번 E pulse 정상
7. OUT Q0~Q7 → LCD D0~D7 순서 정상
8. 문자 `A` 출력
9. 문자열 출력
10. Clear Display 명령

Monitor 최종 화면 예:

```text
MAKECOMPUTER/8
SYSTEM READY
> _
```

# 10-17. PS/2 키보드 테스트

A키부터 시험한다.

1. PS/2 CLOCK 확인
2. PS/2 DATA 확인
3. 74HC161 비트 카운터 증가 확인
4. 74HC164 Scan Code 확인
5. ASCII ROM 출력 확인
6. KEY_READY=1 확인
7. 주소 161에서 `0x41` 확인
8. CPU가 읽은 뒤 KEY_READY=0 확인
9. 다음 키를 다시 받을 수 있는지 확인

A키가 성공한 뒤 B, C, 숫자 등으로 늘린다.

# 10-18. 최종 Monitor 기능

목표 Monitor 기능:

```text
H       HELP
M aa    MEMORY READ
S aa vv MEMORY WRITE
R aa    RUN
C       CLEAR LCD
```

한 기능씩 따로 시험한다.

특히:

```text
R aa
```

로 RAM 프로그램을 실행한 뒤 Reset하면 다시 Boot ROM Monitor로 돌아와야 한다.

# 문제가 생겼을 때 찾는 순서

전체를 한꺼번에 확인하지 않는다.

## PC가 안 움직임

```text
NE555 3번 RAW_CLK
→ CPU Clock AND 1번
→ CPU Clock AND 3번 CPU_CLK
→ PC 두 74HC161 2번
```

순서로 측정한다.

## RAM 값이 이상함

```text
ADDRESS A0~A7
→ RAM 뱅크 74HC138 출력
→ 선택 RAM 15번 CS
→ RAM 16번 MRD / 17번 MWR
→ 245 #1 1번 DIR / 19번 /OE
→ RAM_D0~D7
→ DB0~DB7
```

순서로 확인한다.

## ALU 값이 이상함

```text
A 레지스터 Q0~Q7
RAM_D0~RAM_D7
SUB_MODE
두 74HC86 출력
하위 74HC283
하위 COUT → 상위 CIN
상위 74HC283
```

순서로 확인한다.

## 명령이 이상함

```text
IR Q0~Q7
→ 기본/확장 74HC139
→ T0~T5
→ 해당 제어 게이트
→ 실제 제어 대상 핀
```

순서로 확인한다.
